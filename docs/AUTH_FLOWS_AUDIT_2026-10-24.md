## Server-side idempotency (checked, not rewritten)

- `POST /v1/groups/join` — idempotent (`already_member`).
- `POST /v1/assignments/:a/submit` — data idempotent (`ON CONFLICT DO NOTHING`), second call answers
  `409 already_submitted`; the app now shares one in-flight submission so the user never sees that error
  from a double tap.
- `POST /v1/groups`, `POST /v1/groups/:g/assignments`, community questions/answers — **not** idempotent
  (random ids). Protected on the client only; a server idempotency key would need a schema change (not done).
- Admin delete/revoke — single use per step-up on the server, so a duplicated request after one code
  cannot run twice.
